17.3 Your Three Projects -- What Makes Sense

Task Manager -- SQLite is perfect as a CLI tool. If you later add a web interface (Flask/FastAPI), migrate to PostgreSQL.

Notes Manager -- SQLite for local use. The tags (many-to-many) work identically in both. SQLite first, then migrate if you ever host it.

Banking Simulation -- This benefits from PostgreSQL now. Real bank transfers need strong transaction support and strict types. Good practice to start with PostgreSQL here.

17.4 Writing Code That Works With Both

class Database:
    def __init__(self, db_type="sqlite", **kwargs):
        self.db_type = db_type
        if db_type == "sqlite":
            import sqlite3
            self.conn = sqlite3.connect(kwargs["path"])
        else:
            import psycopg2
            self.conn = psycopg2.connect(**kwargs)

    def placeholder(self):
        return "?" if self.db_type == "sqlite" else "%s"

17.5 Where to Go From Here

  • · SQLAlchemy -- the standard Python ORM, works with both SQLite and PostgreSQL
  • · Alembic -- database migrations (evolving your schema over time)
  • · asyncpg -- async PostgreSQL driver for FastAPI / async Python
  • · Supabase -- hosted PostgreSQL with a free tier, great for side projects
  • · Indexes -- make queries on large tables fast (CREATE INDEX)
