CRUD with sqlite3

Create, Read, Update, Delete from Python. You will build a complete, reusable storage layer for your task manager, one function at a time.

What you will learn
  • The four CRUD operations as Python functions, each one explained line by line
  • lastrowid and rowcount: how SQLite tells you what happened
  • Reading rows: tuples, sqlite3.Row and dicts
  • A reusable connect() helper so you stop repeating boilerplate
  • Moving your JSON-based task manager into SQLite

11.1 The plan: a storage layer

CRUD stands for Create, Read, Update, Delete: the four things every app does with its data. You already know the SQL for each. The job now is to wrap each one in a small Python function so the rest of your program never touches SQL directly. That wrapper is called a storage layer.

OperationSQLOur functionFinishes with
CreateINSERTadd_task(title, priority)cur.lastrowid: the new id
ReadSELECTget_task(id), get_tasks(status)fetchone() / fetchall()
UpdateUPDATEupdate_status(id, status)cur.rowcount: rows changed
DeleteDELETEdelete_task(id)cur.rowcount: rows removed

One helper instead of the same four lines everywhere

From Chapter 10, every function needs: open connection, wrap in with to commit or roll back, close at the end. Writing that in every function is noisy and easy to get wrong, so we write it once:

import sqlite3
from contextlib import contextmanager
from datetime import datetime

DB = "tasks.db"

@contextmanager
def connect():
    conn = sqlite3.connect(DB)
    try:
        with conn:              # commit on success, rollback on error
            yield conn          # <- your code in the "with connect()" block runs here
    finally:
        conn.close()            # always runs, even after an error

The @contextmanager decorator turns a function into something you can use with with. Everything before yield runs when the block starts; everything after runs when it ends:

1 · opensqlite3.connect(DB) runs.
2 · your codeThe body of with connect() as conn: runs at yield.
3 · commit / rollbackInner with conn: commit if no error, rollback if an exception.
4 · closefinally closes the connection no matter what.

You do not need to understand generators to use it: just treat with connect() as conn: as “safe database session”. Now the table setup:

def init_db():
    with connect() as conn:
        conn.execute("""
            CREATE TABLE IF NOT EXISTS tasks (
                id         INTEGER PRIMARY KEY AUTOINCREMENT,
                title      TEXT NOT NULL,
                status     TEXT NOT NULL DEFAULT 'pending',
                priority   TEXT NOT NULL DEFAULT 'medium',
                created_at TEXT NOT NULL
            )""")

11.2 Create: INSERT

def add_task(title, priority="medium"):
    with connect() as conn:
        cur = conn.execute(
            "INSERT INTO tasks (title, priority, created_at) VALUES (?, ?, ?)",

11.3 Read: SELECT

From Chapter 10: execute runs the query, a fetch method moves the rows into Python. Reading needs no commit, but we still use connect() for the open-and-close handling.

def get_all_tasks():
    with connect() as conn:
        cur = conn.execute("SELECT id, title, status FROM tasks ORDER BY id DESC")
        return cur.fetchall()            # a list of tuples

for row in get_all_tasks():
    print(f"[{row[0]}] {row[1]} -- {row[2]}")
[3] Buy domain -- pending
[2] Email Kwame -- complete
[1] Learn sqlite3 -- pending

When you want exactly one row (look up by id), use fetchone(). It returns the row, or None if nothing matched, so always check:

with connect() as conn:
    row = conn.execute("SELECT * FROM tasks WHERE id = ?", (99,)).fetchone()

if row is None:
    print("No such task")
Indexing None

row[1] on a missing row crashes with TypeError: 'NoneType' object is not subscriptable. Look-up functions should check for None before using the row.

11.4 Row factories: names instead of numbers

row[1] means “the second column”. Add a column to the SELECT or reorder it, and every index in your code silently points at the wrong thing. A row factory changes what kind of object each row is. One extra line in connect():

conn = sqlite3.connect(DB)
conn.row_factory = sqlite3.Row         # <- add this line right after connect
Default (tuple)sqlite3.Rowdict(row)
by position row[1]yesyesno
by name row["title"]noyesyes
print it(1, 'x', 'pending')<sqlite3.Row ...> (unreadable){'id': 1, 'title': 'x', ...}
convert to JSONawkwardnoyes: ready for json.dumps

The pattern: use Row while you work with the cursor, then convert to plain dicts with dict(row) before returning. Now the finished read functions, including an optional filter:

def get_task(task_id):
    with connect() as conn:
        row = conn.execute("SELECT * FROM tasks WHERE id = ?", (task_id,)).fetchone()
        return dict(row) if row else None

def get_tasks(status=None):
    sql = "SELECT * FROM tasks"
    params = []
    if status is not None:
        sql += " WHERE status = ?"
        params.append(status)
    sql += " ORDER BY id"
    with connect() as conn:
        return [dict(r) for r in conn.execute(sql, params)]

Two things to notice. First, get_tasks adds text you wrote (" WHERE status = ?") to the SQL, but the user's value still travels through the ? and params. That is safe. Second, you can loop straight over the cursor (for r in conn.execute(...)) without calling fetchall().

11.5 Update: UPDATE

def update_status(task_id, status):
    with connect() as conn:
        cur = conn.execute("UPDATE tasks SET status = ? WHERE id = ?", (status, task_id))
        return cur.rowcount > 0          # True if a row was actually changed

cur.rowcount is how many rows the statement changed. This matters because updating a task that does not exist is not an error: SQL happily changes zero rows and says nothing. Checking rowcount lets your function report it:

update_status(2, "complete")     # True   (task 2 exists)
update_status(99, "complete")    # False  (nothing matched; no error was raised)
UPDATE without WHERE changes every row

UPDATE tasks SET status = ? with the WHERE id = ? left off marks all tasks. Compare:

11.6 Delete: DELETE

def delete_task(task_id):
    with connect() as conn:
        cur = conn.execute("DELETE FROM tasks WHERE id = ?", (task_id,))
        return cur.rowcount > 0

delete_task(3)     # True
delete_task(3)     # False   already gone
Delete is permanent

There is no undo once the transaction commits. For anything a user might regret deleting, many apps instead add a status such as 'archived' and hide those rows (a “soft delete”). That is an UPDATE, not a DELETE.

Single-value tuples need a trailing comma

(task_id) is just brackets around a number. (task_id,) is a one-element tuple. The comma is what makes the tuple, and sqlite3 needs a sequence even for one parameter.

11.7 The finished module

Everything together in one file, tasks.py, plus a short demo at the bottom:

import sqlite3
from contextlib import contextmanager
from datetime import datetime

DB = "tasks.db"

@contextmanager
def connect():
    conn = sqlite3.connect(DB)
    conn.row_factory = sqlite3.Row
    try:
        with conn:
            yield conn
    finally:
        conn.close()

def init_db():
    with connect() as conn:
        conn.execute("""
            CREATE TABLE IF NOT EXISTS tasks (
                id         INTEGER PRIMARY KEY AUTOINCREMENT,
                title      TEXT NOT NULL,
                status     TEXT NOT NULL DEFAULT 'pending',
                priority   TEXT NOT NULL DEFAULT 'medium',
                created_at TEXT NOT NULL
            )""")

def add_task(title, priority="medium"):
    with connect() as conn:
        cur = conn.execute(
            "INSERT INTO tasks (title, priority, created_at) VALUES (?, ?, ?)",
            (title, priority, datetime.now().isoformat(timespec="seconds")))
        return cur.lastrowid

def get_task(task_id):
    with connect() as conn:
        row = conn.execute("SELECT * FROM tasks WHERE id = ?", (task_id,)).fetchone()
        return dict(row) if row else None

def get_tasks(status=None):
    sql = "SELECT * FROM tasks"
    params = []
    if status is not None:
        sql += " WHERE status = ?"
        params.append(status)
    sql += " ORDER BY id"
    with connect() as conn:
        return [dict(r) for r in conn.execute(sql, params)]

def update_status(task_id, status):
    with connect() as conn:
        cur = conn.execute("UPDATE tasks SET status = ? WHERE id = ?", (status, task_id))
        return cur.rowcount > 0

def delete_task(task_id):
    with connect() as conn:
        cur = conn.execute("DELETE FROM tasks WHERE id = ?", (task_id,))
        return cur.rowcount > 0

if __name__ == "__main__":
    init_db()
    a = add_task("Learn sqlite3", "high")
    b = add_task("Email Kwame")
    c = add_task("Buy domain", "low")
    update_status(b, "complete")
    delete_task(c)
    print(update_status(99, "complete"))            # no such task
    for t in get_tasks():
        print(t["id"], t["title"], t["status"], t["priority"])
False
1 Learn sqlite3 pending high
2 Email Kwame complete medium

if __name__ == "__main__": means the demo runs only when you run tasks.py directly. When another file does import tasks, the demo is skipped. Run the file twice and you will see duplicate rows, because each run inserts fresh tasks. Delete tasks.db to start clean.

11.8 Migrating your JSON data into SQLite

If your task manager already stores tasks in a JSON file, you can move them in one batch. Adjust the key names to match your file:

import json

def migrate_json(path):
    with open(path, encoding="utf-8") as f:
        old_tasks = json.load(f)                  # assumed: a list of dicts

    now = datetime.now().isoformat(timespec="seconds")
    rows = [
        (t["title"], t.get("priority", "medium"), t.get("status", "pending"), t.get("created_at", now))
        for t in old_tasks
    ]
    with connect() as conn:
        conn.executemany(
            "INSERT INTO tasks (title, priority, status, created_at) VALUES (?, ?, ?, ?)", rows)
    return len(rows)

print(migrate_json("tasks.json"), "tasks migrated")

Three habits that make migrations safe: keep the JSON file until you have checked the result (compare len(get_tasks()) with the old count); run it once, since a second run inserts everything again; and rely on the with block, so if one row is bad (say a missing title) nothing is inserted, instead of half your data.

Exercises
Q1 — fetchone() returns what when no rows match?
  • A An empty list []
  • B None
  • C It raises an exception
fetchone() gives back None when there is no row. Always check if row is None before indexing it. (fetchall() is the one that returns [].)
Q2 — What does conn.row_factory = sqlite3.Row do?
  • A Makes queries faster
  • B Lets you read columns by name as well as by position
  • C Converts results to JSON
Row objects support row["title"] and row[1]. Convert with dict(row) when you need a plain dictionary or JSON.
Q3 — You call update_status(99, 'done') and no task has id 99. What happens?
  • A sqlite3 raises an error
  • B Nothing is changed and no error is raised; rowcount is 0
  • C A new task with id 99 is created
UPDATE and DELETE on a non-matching WHERE simply affect zero rows. Check cur.rowcount if you need to know.
Q4 — What does cur.lastrowid give you after an INSERT?
  • A The number of rows inserted
  • B The id SQLite assigned to the new row
  • C The total number of rows in the table
lastrowid is the primary key of the row you just inserted, which you need to refer to it later.
Mini-project: extend the storage layer

Add to tasks.py:

1. count_by_status() returns a dict like {'pending': 2, 'complete': 1} (hint: GROUP BY from Chapter 9).
2. rename_task(task_id, new_title) returns True if a task was renamed, False if the id does not exist.
3. Stretch: get_tasks also accepts priority=None and filters by both when given.

def count_by_status():
    with connect() as conn:
        rows = conn.execute("SELECT status, COUNT(*) AS n FROM tasks GROUP BY status")
        return {r["status"]: r["n"] for r in rows}

def rename_task(task_id, new_title):
    with connect() as conn:
        cur = conn.execute("UPDATE tasks SET title = ? WHERE id = ?", (new_title, task_id))
        return cur.rowcount > 0

# Stretch: build the WHERE from a list of conditions
def get_tasks(status=None, priority=None):
    sql, params, conds = "SELECT * FROM tasks", [], []
    if status is not None:
        conds.append("status = ?");   params.append(status)
    if priority is not None:
        conds.append("priority = ?"); params.append(priority)
    if conds:
        sql += " WHERE " + " AND ".join(conds)       # only YOUR text is joined here
    with connect() as conn:
        return [dict(r) for r in conn.execute(sql + " ORDER BY id", params)]
