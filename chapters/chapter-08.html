Joins

Joins are where relational databases show their real power. This is how you connect data across multiple tables — like your notes and their tags.

🎯 What you'll learn
  • Why multiple tables exist and how they relate
  • Foreign keys — the link between tables
  • INNER JOIN — rows that match in both tables
  • LEFT JOIN — all rows from one table, matched or not
  • Junction tables for many-to-many relationships

8.1 Why Multiple Tables?

Imagine storing tasks with their assigned user:

Bad — repeated data: tasks ┌────┬──────────────────┬────────────┬──────────────────┐ │ id │ title │ user_name │ user_email │ ├────┼──────────────────┼────────────┼──────────────────┤ │ 1 │ Learn SQL │ Samuel │ samuel@email.com │ │ 2 │ Build project │ Samuel │ samuel@email.com │ │ 3 │ Write tests │ Kwame │ kwame@email.com │ └────┴──────────────────┴────────────┴──────────────────┘ Problem: if Samuel changes his email, you update multiple rows. Problem: storing the same data in multiple places wastes space and causes inconsistency.

The solution is two tables, with a foreign key linking them:

users tasks ┌────┬────────┬──────────────────┐ ┌────┬──────────────┬─────────┐ │ id │ name │ email │ │ id │ title │ user_id │ ├────┼────────┼──────────────────┤ ├────┼──────────────┼─────────┤ │ 1 │ Samuel │ samuel@email.com │ │ 1 │ Learn SQL │ 1 │ │ 2 │ Kwame │ kwame@email.com │ │ 2 │ Build project│ 1 │ └────┴────────┴──────────────────┘ │ 3 │ Write tests │ 2 │ └────┴──────────────┴─────────┘ tasks.user_id → users.id (foreign key)

8.2 INNER JOIN

Returns rows where there's a match in both tables:

SELECT tasks.title, users.name
FROM tasks
INNER JOIN users ON tasks.user_id = users.id;
Result: ┌──────────────┬────────┐ │ title │ name │ ├──────────────┼────────┤ │ Learn SQL │ Samuel │ │ Build project│ Samuel │ │ Write tests │ Kwame │ └──────────────┴────────┘

Use table aliases to keep queries short:

SELECT t.title, u.name
FROM tasks t
JOIN users u ON t.user_id = u.id;
-- INNER JOIN and JOIN are identical

8.3 LEFT JOIN

Returns all rows from the left table, plus matched rows from the right. Unmatched right-side columns are NULL:

SELECT u.name, t.title
FROM users u
LEFT JOIN tasks t ON t.user_id = u.id;
Result — includes users with no tasks: ┌────────┬──────────────┐ │ name │ title │ ├────────┼──────────────┤ │ Samuel │ Learn SQL │ │ Samuel │ Build project│ │ Kwame │ Write tests │ │ Abena │ NULL │ ← Abena has no tasks └────┴──────────────┘

8.4 Many-to-Many — Junction Tables

A note can have many tags. A tag can belong to many notes. This is a many-to-many relationship — exactly what you built in your notes manager with JSON arrays.

In SQL, you solve this with a junction table:

CREATE TABLE notes (
    id    INTEGER PRIMARY KEY,
    title TEXT    NOT NULL
);

CREATE TABLE tags (
    id   INTEGER PRIMARY KEY,
    name TEXT    NOT NULL UNIQUE
);

CREATE TABLE note_tags (    -- junction table
    note_id INTEGER REFERENCES notes(id),
    tag_id  INTEGER REFERENCES tags(id),
    PRIMARY KEY (note_id, tag_id)
);

Now query all notes with the "python" tag:

SELECT n.title
FROM notes n
JOIN note_tags nt ON n.id = nt.note_id
JOIN tags t       ON nt.tag_id = t.id
WHERE t.name = 'python';

That filtering function you wrote in Python — 15+ lines of JSON looping — is now one SQL query.

📝 Exercises
Q1 — What's the difference between INNER JOIN and LEFT JOIN?
  • A INNER JOIN is faster; LEFT JOIN is more accurate
  • B INNER JOIN only returns rows with matches in both tables; LEFT JOIN returns all left rows even without a match
  • C They are identical
INNER JOIN = intersection. Only rows that match on both sides. LEFT JOIN = all left rows, matched right rows where they exist, NULL where they don't. Use LEFT JOIN when you want "all X, even those with no Y".
Q2 — Why does a many-to-many relationship need a junction table?
  • A It doesn't — you can store a list in one column
  • B To make queries faster
  • C Because a column can only store one value — a junction table stores one row per relationship pair
Each cell in a relational database holds one value. To represent "note 1 has tags python, learning, reference" you need three rows in the junction table: (1, python_id), (1, learning_id), (1, reference_id). This is exactly what you were mimicking with JSON arrays.
🧠 Checkpoint

Write a query that returns the title of every note along with all its tag names. Notes with no tags should still appear (with NULL for the tag name).

SELECT n.title, t.name AS tag
FROM notes n
LEFT JOIN note_tags nt ON n.id = nt.note_id
LEFT JOIN tags t       ON nt.tag_id = t.id
ORDER BY n.title, t.name;
