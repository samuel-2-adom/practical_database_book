What Is a Database?

Before writing a single line of SQL or Python, you need to understand what a database actually is — and why files alone aren't enough.

🎯 What you'll learn
  • What a database is and why programs need one
  • How a database differs from a plain text file or CSV
  • What a relational database is
  • What SQL is and where it fits in
  • The difference between SQLite and PostgreSQL

1.1 Why Not Just Use a File?

Imagine you're building a contact book. The simplest approach is a text file:

Samuel, samuel@email.com, 0244123456
Kwame, kwame@email.com, 0201987654
Abena, abena@email.com, 0557654321

This works fine for a handful of contacts. But what happens when you want to:

  • · Find everyone whose name starts with "A"?
  • · Update just one person's phone number?
  • · Store 50,000 contacts and find one instantly?
  • · Have two programs reading and writing at the same time?
  • · Make sure a half-written save doesn't corrupt everything?

A plain file forces you to write all of that logic yourself. A database handles it for you — and handles it fast, safely, and correctly.

🔵 What a database actually is

A database is a program that stores data in a structured way and lets you query, update, and manage it efficiently. It handles things like searching, indexing, concurrent access, and preventing corruption — so you don't have to.

1.2 Relational Databases

There are many kinds of databases. This book covers relational databases — the most common kind, and the one you'll encounter in almost every real application.

A relational database stores data in tables — like spreadsheets, but much more powerful. Each table has rows and columns, and tables can be linked to each other.

contacts table ┌────┬──────────┬───────────────────┬─────────────┐ │ id │ name │ email │ phone │ ├────┼──────────┼───────────────────┼─────────────┤ │ 1 │ Samuel │ samuel@email.com │ 0244123456 │ │ 2 │ Kwame │ kwame@email.com │ 0201987654 │ │ 3 │ Abena │ abena@email.com │ 0557654321 │ └────┴──────────┴───────────────────┴─────────────┘

That looks like a spreadsheet — and that's intentional. The concept is familiar. The difference is what you can do with it: filter rows instantly, join multiple tables, update millions of records in one command, and much more.

1.3 What Is SQL?

SQL — Structured Query Language — is the language you use to talk to a relational database. It's been around since the 1970s and is still the standard today. Every relational database understands SQL.

SQL looks like readable English:

SELECT name, email
FROM contacts
WHERE name LIKE 'A%';

"Give me the name and email of every contact whose name starts with A."

UPDATE contacts
SET phone = '0244999888'
WHERE id = 1;

"Update the phone number for the contact with id 1."

You'll be writing SQL like this fluently by the end of Part I.

1.4 SQLite vs PostgreSQL

Both are relational databases. Both speak SQL. But they work differently:

SQLite PostgreSQL
Setup Zero — built into Python Install a server
Storage A single .db file Managed by the server
Connections One user at a time (usually) Many simultaneous users
Best for Local tools, prototypes, learning Web apps, production, teams
Python library sqlite3 (built-in, no install) psycopg2 (pip install)
💡 Which should you use?

SQLite for anything local — CLI tools, desktop apps, personal projects, prototypes. PostgreSQL when you need a server, multiple users, or production-grade reliability. This book teaches both, starting with SQLite because it requires zero setup.

1.5 How Python Fits In

SQL is the language for talking to databases. Python is the program doing the talking. The flow looks like this:

Your Python program │ │ SQL query (as a string) ▼ Database driver (sqlite3 or psycopg2) │ │ sends to database engine ▼ Database │ │ results (rows of data) ▼ Python list of tuples │ ▼ Your program uses the data

You write SQL inside Python strings. The database driver sends it to the database, gets the results back, and hands them to you as Python data structures — lists, tuples, dictionaries — that you already know how to work with.

📝 Check Your Understanding
Question 1 — What is the main advantage of a database over storing data in a plain text file?
  • A Databases use less disk space
  • B Databases are easier to open in a text editor
  • C Databases handle searching, updating, concurrent access, and data integrity efficiently
A database isn't just storage — it's a program that manages data intelligently. It can find one row among millions instantly, update records safely, handle multiple users at once, and prevent corruption. A text file can do none of that without custom code.
Question 2 — What does SQL stand for?
  • A Simple Query Library
  • B Structured Query Language
  • C Standard Question Logic
SQL — Structured Query Language — is the standard language for relational databases. It's been around since the 1970s and is still universal today. Every relational database (SQLite, PostgreSQL, MySQL, Oracle) understands SQL.
Question 3 — You're building a personal CLI expense tracker for your own computer. Which database makes more sense?
  • A SQLite — zero setup, single file, built into Python
  • B PostgreSQL — more powerful and production-ready
  • C Neither — use a CSV file
SQLite is perfect for local personal tools. No server to install, no configuration, the whole database is one .db file, and sqlite3 is already in Python's standard library. PostgreSQL's power would be overkill here — save it for when you have multiple users or need a server.
Question 4 — What does Python receive back after sending a SQL query to a database?
  • A A raw SQL response string
  • B An HTML table
  • C Python data structures — lists of tuples or dictionaries
The database driver (sqlite3 or psycopg2) translates the database's response into native Python types. You get back lists of tuples by default, which you can loop over, index into, and work with just like any other Python data.

📌 What to remember from this chapter

· A database stores data structurally and handles searching, updating, and concurrent access

· Relational databases organise data in tables with rows and columns

· SQL is the language for talking to relational databases

· SQLite — zero setup, one file, built into Python. Local tools.

· PostgreSQL — server-based, production-grade, multi-user. Real apps.

· SQL is the same in both — only the connection code changes
