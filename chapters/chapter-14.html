Intro to PostgreSQL

Part III. SQLite is one .db file. PostgreSQL is a real server -- multi-user, production-grade, what most real applications use.

What you will learn
  • How PostgreSQL differs from SQLite architecturally
  • Installing PostgreSQL and creating a database
  • Connecting with psycopg2
  • Key SQL syntax differences between SQLite and PostgreSQL
PostgreSQL setup required

PostgreSQL runs as a separate server process. Install from postgresql.org, then: pip install psycopg2-binary

14.1 Installing PostgreSQL

Download from postgresql.org/download for your OS. After installing, open psql and create a database:

psql -U postgres
CREATE DATABASE myproject;
CREATE USER myuser WITH PASSWORD 'mypassword';
GRANT ALL PRIVILEGES ON DATABASE myproject TO myuser;

14.2 Connecting

import psycopg2, os

conn = psycopg2.connect(
    dbname=os.environ["DB_NAME"],
    user=os.environ["DB_USER"],
    password=os.environ["DB_PASS"],
    host=os.environ.get("DB_HOST", "localhost")
)
Never hardcode credentials

Store connection details in environment variables. Same rule as API keys in the HTTP book.

14.3 Key Differences from SQLite

SQLitePostgreSQL
Auto-increment PKINTEGER PRIMARY KEYSERIAL PRIMARY KEY
BooleanINTEGER (0/1)BOOLEAN (true/false)
TimestampsTEXT (ISO string)TIMESTAMP / TIMESTAMPTZ
Query placeholder?%s
Auto-commitYes (context manager)No -- must commit explicitly
The biggest difference: %s not ?

psycopg2 uses %s as the placeholder, not ?. This is the most common gotcha when switching. Everything else is nearly identical.

Exercises
Q1 -- What placeholder does psycopg2 use?
  • A ?
  • B %s
  • C {}
psycopg2 uses %s. Despite looking like Python string formatting, psycopg2 handles it safely via the database driver. Never use actual % string formatting for SQL.
Q2 -- How do you define an auto-incrementing PK in PostgreSQL?
  • A INTEGER PRIMARY KEY
  • B AUTO_INCREMENT PRIMARY KEY
  • C SERIAL PRIMARY KEY
PostgreSQL uses SERIAL for auto-incrementing integers. In modern PostgreSQL you can also use GENERATED ALWAYS AS IDENTITY.
