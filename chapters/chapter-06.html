Creating & Modifying Tables

So far you've queried tables that already exist. Now you'll build them yourself — defining their structure, constraints, and rules.

🎯 What you'll learn
  • CREATE TABLE — defining a table from scratch
  • Column constraints: NOT NULL, UNIQUE, DEFAULT
  • ALTER TABLE — modifying an existing table
  • DROP TABLE — deleting a table
  • Designing a schema for your own projects

6.1 CREATE TABLE

CREATE TABLE tasks (
    id          INTEGER   PRIMARY KEY,
    title       TEXT      NOT NULL,
    status      TEXT      NOT NULL DEFAULT 'pending',
    priority    TEXT      NOT NULL DEFAULT 'medium',
    created_at  TEXT      NOT NULL
);

Breaking it down:

id INTEGER PRIMARY KEY │ │ │ │ │ └── this column uniquely identifies each row │ └────────── data type: whole numbers └────────────── column name title TEXT NOT NULL │ └── this column must always have a value (never NULL) status TEXT NOT NULL DEFAULT 'pending' │ └── if no value given, use 'pending'

6.2 CREATE TABLE IF NOT EXISTS

If you run CREATE TABLE twice on the same table, you get an error. Use IF NOT EXISTS to avoid this — useful when your Python program creates the table on startup:

CREATE TABLE IF NOT EXISTS tasks (
    id    INTEGER PRIMARY KEY,
    title TEXT    NOT NULL
);

6.3 Column Constraints

ConstraintMeaning
PRIMARY KEYUnique, never NULL, identifies the row
NOT NULLColumn must always have a value
UNIQUENo two rows can have the same value
DEFAULT valueUse this value if none is provided
CHECK (condition)Value must satisfy this condition
CREATE TABLE users (
    id       INTEGER PRIMARY KEY,
    username TEXT    NOT NULL UNIQUE,
    email    TEXT    NOT NULL UNIQUE,
    age      INTEGER CHECK(age >= 0)
);

6.4 ALTER TABLE

Add a column to an existing table:

ALTER TABLE tasks
ADD COLUMN due_date TEXT;
⚠️ SQLite ALTER TABLE is limited

SQLite only supports ADD COLUMN — you can't rename or drop a column directly. PostgreSQL supports the full ALTER TABLE spec including RENAME COLUMN, DROP COLUMN, and ALTER COLUMN. Plan your schema carefully before building on SQLite.

6.5 DROP TABLE

DROP TABLE tasks;              -- error if table doesn't exist
DROP TABLE IF EXISTS tasks;   -- safe version
⚠️ DROP TABLE is permanent

DROP TABLE deletes the table and all its data instantly, with no undo. There is no recycle bin. Always double-check before running it, and never run it in a script without IF EXISTS as a safety check.

6.6 Designing Your Tasks Table

Here's a well-designed schema for the task manager you already built in Python — this is exactly the table you'll create in Part II:

CREATE TABLE IF NOT EXISTS tasks (
    id          INTEGER  PRIMARY KEY,
    title       TEXT     NOT NULL,
    description TEXT,
    status      TEXT     NOT NULL DEFAULT 'pending'
                         CHECK(status IN ('pending','in_progress','complete')),
    priority    TEXT     NOT NULL DEFAULT 'medium'
                         CHECK(priority IN ('low','medium','high')),
    created_at  TEXT     NOT NULL
);
📝 Exercises
Q1 — What does DEFAULT 'pending' do in a column definition?
  • A Forces every row to have the value 'pending'
  • B Uses 'pending' if no value is provided when inserting a row
  • C Renames the column to 'pending'
DEFAULT provides a fallback value. If you INSERT a row without providing a value for that column, the database uses the default. You can still override it by providing your own value.
Q2 — Which keyword makes it safe to run CREATE TABLE even if the table already exists?
  • A CREATE OR REPLACE TABLE
  • B CREATE SAFE TABLE
  • C CREATE TABLE IF NOT EXISTS
IF NOT EXISTS makes the statement a no-op if the table already exists, instead of raising an error. Essential for Python programs that create tables on startup — you don't want it to fail on the second run.
🧠 Checkpoint — Design Your Notes Table

Write the CREATE TABLE statement for your notes manager. Include: id (primary key), title (required), content, created_at (required), and updated_at. Add appropriate constraints.

CREATE TABLE IF NOT EXISTS notes (
    id         INTEGER PRIMARY KEY,
    title      TEXT    NOT NULL,
    content    TEXT,
    created_at TEXT    NOT NULL,
    updated_at TEXT
