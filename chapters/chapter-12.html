Part II -- SQLite + Python -- Chapter 12

Parameterised Queries

The question marks you have been using are not just convenient -- they are essential for security. This chapter explains SQL injection and why parameterised queries prevent it.

What you will learn
  • What SQL injection is and why it matters
  • How parameterised queries prevent it
  • Named parameters -- cleaner syntax for many values
  • Inserting many rows efficiently with executemany

12.1 The Problem -- SQL Injection

Imagine you build a search using string formatting:

# DANGEROUS -- never do this
user_input = "' OR '1'='1"
query = f"SELECT * FROM users WHERE name = '{user_input}'"
# becomes: SELECT * FROM users WHERE name = '' OR '1'='1'
# returns ALL rows -- security disaster

An attacker can manipulate your SQL by injecting their own SQL through the input. This is called SQL injection -- one of the most common and dangerous web vulnerabilities.

12.2 The Solution -- Parameterised Queries

# SAFE -- always do this
user_input = "' OR '1'='1"
conn.execute("SELECT * FROM users WHERE name = ?", (user_input,))
# sqlite3 treats the input as a value, not SQL
# returns zero rows -- correct behaviour

The ? is a placeholder. sqlite3 sends the query and the parameters separately -- the database never mixes them, so injected SQL is impossible.

Never build SQL with string formatting

Not f-strings, not % formatting, not + concatenation. Always use ? placeholders. No exceptions. This applies to all user input, file content, API data -- any external value.

12.3 Named Parameters -- Cleaner for Many Values

When you have many parameters, positional ? gets confusing. Use named parameters instead:

from datetime import datetime

task = {
    "title":    "Learn parameterised queries",
    "priority": "high",
    "status":   "pending",
    "created":  datetime.now().isoformat(),
}

conn.execute(
    "INSERT INTO tasks (title, priority, status, created_at) VALUES (:title, :priority, :status, :created)",
    task
)

12.4 executemany -- Batch Inserts

tasks = [
    ("Task one",   "high",   "2024-01-01"),
    ("Task two",   "medium", "2024-01-02"),
    ("Task three", "low",    "2024-01-03"),
]

with sqlite3.connect("tasks.db") as conn:
    conn.executemany(
        "INSERT INTO tasks (title, priority, created_at) VALUES (?, ?, ?)",
        tasks
    )
# inserts all three rows in one efficient operation
Exercises
Q1 -- What is SQL injection?
  • A A way to speed up SQL queries
  • B Malicious SQL inserted through user input to manipulate database operations
  • C A Python error type
SQL injection occurs when user input is concatenated directly into a SQL string, letting attackers inject their own SQL. Parameterised queries prevent it by keeping values separate from the query structure.
Q2 -- What is the safe way to include a variable in a SQL query?
  • A conn.execute(f"SELECT * FROM tasks WHERE id = {task_id}")
  • B conn.execute("SELECT * FROM tasks WHERE id = " + str(task_id))
  • C conn.execute("SELECT * FROM tasks WHERE id = ?", (task_id,))
Only option C uses a parameterised query. A and B build SQL strings through concatenation -- both are vulnerable to SQL injection.
Checkpoint

Rewrite this unsafe function using parameterised queries:
def find_task(name): conn.execute(f"SELECT * FROM tasks WHERE title = '{name}'")

def find_task(name):
    with sqlite3.connect("tasks.db") as conn:
        conn.row_factory = sqlite3.Row
        cur = conn.execute(
            "SELECT * FROM tasks WHERE title = ?", (name,)
        )
        return [dict(r) for r in cur.fetchall()]
