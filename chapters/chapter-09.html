Aggregates & Grouping

Count, sum, average, find the max and min — and group results by category. This rounds out Part I and makes your queries genuinely useful for reporting.

🎯 What you'll learn
  • Aggregate functions: COUNT, SUM, AVG, MIN, MAX
  • GROUP BY — aggregating per category
  • HAVING — filtering aggregated results
  • Combining aggregates with JOINs

9.1 Aggregate Functions

Aggregate functions collapse multiple rows into a single value:

SELECT COUNT(*)          FROM tasks;              -- total rows
SELECT COUNT(due_date)   FROM tasks;              -- non-NULL due dates
SELECT SUM(amount)       FROM expenses;           -- total amount
SELECT AVG(amount)       FROM expenses;           -- average amount
SELECT MIN(created_at)   FROM tasks;              -- oldest task
SELECT MAX(amount)       FROM expenses;           -- biggest expense
💡 COUNT(*) vs COUNT(column)

COUNT(*) counts all rows including NULLs. COUNT(column) counts only rows where that column is not NULL. Use COUNT(*) to count rows; use COUNT(column) to count non-null values in a specific column.

9.2 GROUP BY

Aggregate per category instead of across all rows:

SELECT status, COUNT(*) AS count
FROM tasks
GROUP BY status;
Result: ┌─────────────┬───────┐ │ status │ count │ ├─────────────┼───────┤ │ pending │ 12 │ │ in_progress │ 3 │ │ complete │ 27 │ └─────────────┴───────┘
SELECT priority, status, COUNT(*) AS count
FROM tasks
GROUP BY priority, status
ORDER BY priority, status;

9.3 HAVING — Filter After Grouping

WHERE filters rows before grouping. HAVING filters groups after aggregation:

-- Tags used on more than 3 notes
SELECT t.name, COUNT(*) AS note_count
FROM tags t
JOIN note_tags nt ON t.id = nt.tag_id
GROUP BY t.name
HAVING COUNT(*) > 3
ORDER BY note_count DESC;
🔵 WHERE vs HAVING

WHERE filters individual rows before they're grouped.

HAVING filters groups after aggregation.

Rule: if the condition involves an aggregate function (COUNT, SUM, AVG...) → use HAVING. Otherwise → use WHERE.

9.4 A Real Dashboard Query

-- Task summary: count and avg per priority, pending only
SELECT
    priority,
    COUNT(*)                    AS total,
    SUM(CASE WHEN status = 'complete'
         THEN 1 ELSE 0 END)   AS done
FROM tasks
GROUP BY priority
ORDER BY
    CASE priority
        WHEN 'high'   THEN 1
        WHEN 'medium' THEN 2
        WHEN 'low'    THEN 3
    END;
📝 Exercises
Q1 — What is the difference between WHERE and HAVING?
  • A They are identical — WHERE and HAVING can always be swapped
  • B WHERE is for text columns; HAVING is for number columns
  • C WHERE filters rows before grouping; HAVING filters groups after aggregation
WHERE happens before GROUP BY — it filters the raw rows. HAVING happens after GROUP BY — it filters the grouped results. You can't use aggregate functions in WHERE; you can in HAVING.
Q2 — You want categories with more than 5 items. Which clause filters this?
  • A HAVING COUNT(*) > 5
  • B WHERE COUNT(*) > 5
  • C FILTER COUNT(*) > 5
COUNT(*) is an aggregate function, so it must be in HAVING, not WHERE. WHERE can't reference aggregate results because aggregation hasn't happened yet at the WHERE stage.
