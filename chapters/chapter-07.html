Inserting, Updating & Deleting

SELECT reads data. INSERT, UPDATE, and DELETE change it. Together these four statements are everything you need to manage data in a table.

🎯 What you'll learn
  • INSERT INTO — adding new rows
  • UPDATE — modifying existing rows
  • DELETE — removing rows
  • The critical importance of WHERE with UPDATE and DELETE

7.1 INSERT INTO

Add a new row to a table:

INSERT INTO tasks (title, status, priority, created_at)
VALUES ('Learn SQL', 'pending', 'high', '2024-01-15');

You don't include id — it auto-increments. Column order must match value order.

Insert multiple rows at once:

INSERT INTO tasks (title, status, priority, created_at)
VALUES
    ('Learn SQL',       'pending', 'high',   '2024-01-15'),
    ('Build project',   'pending', 'medium', '2024-01-16'),
    ('Write tests',     'pending', 'low',    '2024-01-17');

7.2 UPDATE

Change values in existing rows:

UPDATE tasks
SET status = 'complete'
WHERE id = 1;

Update multiple columns at once:

UPDATE tasks
SET status = 'in_progress', priority = 'high'
WHERE id = 2;
⚠️ ALWAYS include WHERE with UPDATE

UPDATE tasks SET status = 'complete' — no WHERE — updates every single row. This is one of the most common and painful mistakes in SQL. Always check your WHERE clause before running an UPDATE.

7.3 DELETE

DELETE FROM tasks WHERE id = 3;

Delete all completed tasks:

DELETE FROM tasks WHERE status = 'complete';
⚠️ ALWAYS include WHERE with DELETE

DELETE FROM tasks — no WHERE — deletes every row in the table. The table structure remains, but all data is gone. No undo. This is the SQL equivalent of rm -rf.

7.4 Safe Pattern — SELECT Before DELETE/UPDATE

Before running a destructive operation, run the equivalent SELECT to check what you'll affect:

-- Step 1: check what you're about to delete
SELECT * FROM tasks WHERE status = 'complete';

-- Step 2: looks right? Now delete
DELETE FROM tasks WHERE status = 'complete';
📝 Exercises
Q1 — What happens if you run UPDATE tasks SET priority = 'high' with no WHERE clause?
  • A Nothing — SQL requires WHERE on UPDATE
  • B Every row in the table gets priority set to 'high'
  • C Only the first row is updated
Without WHERE, UPDATE affects every row. SQL doesn't require WHERE — it's up to you to include it. Always double-check before running.
Q2 — Best practice before running a DELETE?
  • A Run it and hope for the best
  • B Back up the entire database every time
  • C Run SELECT with the same WHERE clause first to verify the affected rows
SELECT first, DELETE second. The WHERE clause is identical — if SELECT returns what you expect, the DELETE will affect exactly those rows. Simple and safe.
🧠 Checkpoint

Write three queries: (1) Insert a new task with title "Migrate to SQLite", high priority. (2) Mark it as in_progress. (3) Delete all tasks where status is 'complete' and priority is 'low'. Use SELECT first for query 3.

-- 1. Insert
INSERT INTO tasks (title, priority, status, created_at)
VALUES ('Migrate to SQLite', 'high', 'pending', '2024-01-20');

-- 2. Update
UPDATE tasks SET status = 'in_progress'
WHERE title = 'Migrate to SQLite';

-- 3a. Verify
SELECT * FROM tasks
WHERE status = 'complete' AND priority = 'low';

-- 3b. Delete
DELETE FROM tasks
WHERE status = 'complete' AND priority = 'low';
