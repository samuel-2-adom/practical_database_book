Filtering with WHERE

SELECT returns everything. WHERE narrows it down. This is where SQL starts to feel powerful.

🎯 What you'll learn
  • The WHERE clause — filtering rows by condition
  • Comparison operators: =, !=, <, >, <=, >=
  • Combining conditions: AND, OR, NOT
  • Pattern matching with LIKE
  • Checking for NULL with IS NULL
  • Matching a list with IN

4.1 The WHERE Clause

WHERE filters which rows are returned. Only rows where the condition is TRUE make it into the result:

SELECT name, email
FROM contacts
WHERE city = 'Accra';

"Give me name and email for contacts whose city is Accra."

4.2 Comparison Operators

WHERE age = 25          -- equals
WHERE age != 25         -- not equal (also: <>)
WHERE age > 18          -- greater than
WHERE age < 65          -- less than
WHERE age >= 18         -- greater than or equal
WHERE age BETWEEN 18 AND 65  -- inclusive range

4.3 AND, OR, NOT

SELECT * FROM tasks
WHERE status = 'pending' AND priority = 'high';
-- both conditions must be true

SELECT * FROM tasks
WHERE status = 'pending' OR status = 'in_progress';
-- either condition can be true

SELECT * FROM tasks
WHERE NOT status = 'complete';
-- condition must be false
⚠️ Use parentheses with AND and OR together

AND has higher precedence than OR. WHERE a OR b AND c is read as WHERE a OR (b AND c) — which may not be what you meant. Always use parentheses to be explicit: WHERE (a OR b) AND c.

4.4 LIKE — Pattern Matching

WHERE name LIKE 'A%'      -- starts with A
WHERE name LIKE '%son'    -- ends with "son"
WHERE name LIKE '%am%'    -- contains "am" anywhere
WHERE name LIKE 'S_m'     -- S, any one character, then m

% matches any number of characters. _ matches exactly one character.

4.5 IN — Match a List

SELECT * FROM tasks
WHERE status IN ('pending', 'in_progress');
-- cleaner than: WHERE status='pending' OR status='in_progress'

4.6 IS NULL / IS NOT NULL

You can't use = NULL to check for NULL. You must use IS NULL:

SELECT * FROM contacts WHERE phone IS NULL;
SELECT * FROM contacts WHERE phone IS NOT NULL;
⚠️ Common mistake — WHERE col = NULL

WHERE phone = NULL always returns zero rows, even if NULL values exist. NULL is not equal to anything, including itself. Always use IS NULL or IS NOT NULL.

📝 Exercises
Q1 — Which query correctly finds all high-priority pending tasks?
  • A SELECT * FROM tasks WHERE status = 'pending' OR priority = 'high';
  • B SELECT * FROM tasks WHERE status AND priority = 'pending' AND 'high';
  • C SELECT * FROM tasks WHERE status = 'pending' AND priority = 'high';
Use AND when both conditions must be true. OR would return tasks that are either pending OR high priority — not necessarily both. Option B is not valid SQL syntax.
Q2 — How do you find rows where the email column has no value?
  • A WHERE email = NULL
  • B WHERE email IS NULL
  • C WHERE email = ''
NULL is not equal to anything — even itself. = NULL always evaluates to unknown (not TRUE), so it never matches. Always use IS NULL. Empty string '' is different — it's a value, just an empty one.
🧠 Checkpoint

Write a query that finds all notes containing the word "python" in the title, that are not archived, and have at least one tag (tags_count > 0).

SELECT * FROM notes
WHERE title LIKE '%python%'
  AND archived = 0
  AND tags_count > 0;
