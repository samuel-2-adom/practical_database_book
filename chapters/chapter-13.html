Transactions and Errors

What happens when something goes wrong mid-operation? Transactions keep your data consistent. This chapter closes out Part II.

What you will learn
  • What a transaction is and why it matters
  • COMMIT and ROLLBACK
  • How the context manager handles transactions automatically
  • Handling database errors in Python

13.1 What Is a Transaction?

A transaction is a group of SQL statements that either all succeed or all fail together. The classic example is a bank transfer:

Transfer GHS 500 from Account A to Account B: Step 1: Deduct 500 from Account A Step 2: Add 500 to Account B If step 2 fails, step 1 must be reversed. Without a transaction, you lose GHS 500 -- deducted but never added.

Transactions guarantee this cannot happen. Either both steps complete (COMMIT) or neither does (ROLLBACK).

13.2 COMMIT and ROLLBACK

with sqlite3.connect("bank.db") as conn:
    try:
        conn.execute("UPDATE accounts SET balance = balance - 500 WHERE id = 1")
        conn.execute("UPDATE accounts SET balance = balance + 500 WHERE id = 2")
        conn.commit()    # both succeeded -- save changes
    except Exception:
        conn.rollback()  # something failed -- undo everything
        raise
The context manager handles this automatically

When you use with sqlite3.connect() as conn, Python commits on a clean exit and rolls back if an exception occurs. You only need explicit commit/rollback for complex multi-step operations.

13.3 Handling Database Errors

import sqlite3

def add_user(username, email):
    try:
        with sqlite3.connect("users.db") as conn:
            conn.execute(
                "INSERT INTO users (username, email) VALUES (?, ?)",
                (username, email)
            )
        return True
    except sqlite3.IntegrityError:
        print(f"Username or email already exists")
        return False
    except sqlite3.OperationalError as e:
        print(f"Database error: {e}")
        return False

13.4 Common sqlite3 Exceptions

sqlite3.Error (base class for all) sqlite3.IntegrityError UNIQUE or NOT NULL violated sqlite3.OperationalError table missing, SQL syntax error sqlite3.ProgrammingError wrong number of parameters
Exercises
Q1 -- What happens to a transaction when an exception occurs inside a with...connect() block?
  • A Changes are saved anyway
  • B The database file is deleted
  • C The transaction is rolled back automatically
The context manager rolls back on exception. Any changes made during the block are undone, leaving the database in its previous state.
Q2 -- You try to insert a username that already exists (UNIQUE constraint). Which exception is raised?
  • A sqlite3.IntegrityError
  • B sqlite3.OperationalError
  • C ValueError
IntegrityError is raised when a constraint is violated -- UNIQUE, NOT NULL, FOREIGN KEY. OperationalError covers structural issues like missing tables or syntax errors.
