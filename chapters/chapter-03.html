Your First SQL Queries

Time to write actual SQL. This chapter covers SELECT — the most important statement in SQL, and the one you'll use more than all others combined.

🎯 What you'll learn
  • The SELECT statement — retrieving data from a table
  • Selecting specific columns vs all columns
  • Column aliases with AS
  • Removing duplicates with DISTINCT

3.1 The SELECT Statement

SELECT is how you ask the database "give me some data". At its simplest:

SELECT * FROM contacts;

The * means "all columns". This returns every column of every row in the contacts table. Think of it as "show me everything".

🔵 Basic SELECT structure
SELECT column1, column2
FROM   table_name;

3.2 Selecting Specific Columns

Almost always, you only want some columns — not all of them. Name the ones you want:

SELECT name, email
FROM contacts;
Result: ┌──────────┬──────────────────────┐ │ name │ email │ ├──────────┼──────────────────────┤ │ Samuel │ samuel@email.com │ │ Kwame │ kwame@email.com │ │ Abena │ abena@email.com │ └──────────┴──────────────────────┘
💡 Avoid SELECT * in real code

SELECT * is fine for exploring data interactively. In real programs, always name your columns explicitly. It makes the code readable, prevents surprises when the table structure changes, and is faster because the database doesn't send columns you don't need.

3.3 Column Aliases with AS

Rename a column in the result using AS:

SELECT
    name        AS full_name,
    email       AS email_address
FROM contacts;

The alias only affects the output — the actual column name in the table is unchanged.

3.4 DISTINCT — Remove Duplicates

If a column has repeated values and you only want unique ones:

SELECT DISTINCT city
FROM contacts;
Without DISTINCT: With DISTINCT: Accra Accra Kumasi Kumasi Accra Tamale Tamale Accra

3.5 SQL Style

SQL keywords are case-insensitive — select works the same as SELECT. Convention is to write keywords in UPPERCASE and table/column names in lowercase. This book follows that convention.

-- Good style
SELECT name, email
FROM contacts;

-- Also works, but harder to read
select name, email from contacts;
📝 Exercises
Q1 — What does SELECT * mean?
  • A Select the first row only
  • B Select all columns
  • C Select all rows but no columns
The * is a wildcard meaning "all columns". SELECT * FROM table returns every column of every row. Fine for exploration, but name your columns explicitly in real code.
Q2 — You want to list all unique cities in a contacts table. Which query?
  • A SELECT city FROM contacts;
  • B SELECT UNIQUE city FROM contacts;
  • C SELECT DISTINCT city FROM contacts;
DISTINCT removes duplicate values from results. UNIQUE is not a valid keyword here — it's used in table creation, not SELECT queries.
🧠 Checkpoint

Write a query that returns only the title and status columns from a tasks table, with no duplicate statuses shown in a second query.

SELECT title, status FROM tasks;

SELECT DISTINCT status FROM tasks;
