Tables, Rows & Columns

Every database is built from tables. This chapter makes sure you understand their structure completely before you write your first query.

🎯 What you'll learn
  • The anatomy of a table: columns, rows, and cells
  • Data types — what kinds of data each column can hold
  • Primary keys and why every table needs one
  • NULL — what it means and when it appears

2.1 Tables Are the Core Unit

Everything in a relational database lives in a table. A table is a collection of related data organised into rows and columns — similar to a spreadsheet, but with strict rules about what goes in each column.

┌─ column name │ ┌─────────┬────────────┬──────────────────────┬──────────┐ │ id │ name │ email │ age │ ← header row (schema) ├─────────┼────────────┼──────────────────────┼──────────┤ │ 1 │ Samuel │ samuel@email.com │ 24 │ ← row (one record) │ 2 │ Kwame │ kwame@email.com │ 31 │ ← row │ 3 │ Abena │ abena@email.com │ 28 │ ← row └─────────┴────────────┴──────────────────────┴──────────┘ ↑ cell (one value)

2.2 Data Types

Every column has a data type — the kind of data it can hold. The database enforces this. You can't store text in an integer column.

TypeSQLite namePostgreSQL nameExample
Whole numberINTEGERINTEGER / BIGINT42, -7, 0
Decimal numberREALNUMERIC / FLOAT3.14, 99.99
TextTEXTVARCHAR(n) / TEXT'Samuel', 'Accra'
True/FalseINTEGER (0/1)BOOLEANtrue, false
Date/TimeTEXT (ISO format)DATE / TIMESTAMP'2024-01-15'
💡 SQLite is flexible with types

SQLite uses "type affinity" — it's more flexible than PostgreSQL and will often accept the wrong type without complaining. PostgreSQL is strict. This book will treat types strictly from the start so you build good habits for both.

2.3 Primary Keys

Every table needs a way to uniquely identify each row. That's the primary key — a column (usually id) whose value is unique for every row and never NULL.

CREATE TABLE users (
    id      INTEGER  PRIMARY KEY,   -- unique identifier
    name    TEXT     NOT NULL,
    email   TEXT     UNIQUE NOT NULL
);

In SQLite, INTEGER PRIMARY KEY auto-increments — each new row gets the next number automatically. In PostgreSQL you use SERIAL or GENERATED ALWAYS AS IDENTITY.

2.4 NULL — The Absence of a Value

NULL means "no value" — not zero, not an empty string, but the complete absence of data. A phone number column might be NULL if the user didn't provide one.

INSERT INTO users (name, email, phone)
VALUES ('Samuel', 's@email.com', NULL);
-- phone is unknown, not provided
⚠️ NULL is not zero or empty string

NULL, 0, and '' are three different things. NULL means the value is unknown or not applicable. This catches beginners out constantly — we'll come back to it when filtering in Chapter 4.

2.5 A Real Table Design

Here's how the task manager you already built might look as a database table:

tasks ┌────┬──────────────────────┬───────────┬─────────────┬─────────────────────┐ │ id │ title │ status │ priority │ created_at │ ├────┼──────────────────────┼───────────┼─────────────┼─────────────────────┤ │ 1 │ Learn SQL basics │ complete │ high │ 2024-01-10 09:00:00 │ │ 2 │ Build expense tracker│ pending │ medium │ 2024-01-11 14:30:00 │ │ 3 │ Read chapter 3 │ pending │ low │ 2024-01-12 08:00:00 │ └────┴──────────────────────┴───────────┴─────────────┴─────────────────────┘

Each row is one task. Each column is one attribute of that task. The id uniquely identifies each task.

📝 Exercises
Q1 — What is a primary key?
  • A The first column in any table
  • B A column whose value uniquely identifies each row and is never NULL
  • C The most important piece of data in a row
A primary key uniquely identifies every row in the table. No two rows can have the same primary key value, and it can never be NULL. It's how you refer to a specific record from elsewhere in the database.
Q2 — A user doesn't provide a phone number when signing up. What should the phone column contain?
  • A 0
  • B An empty string ""
  • C NULL
NULL is the correct value for "not provided" or "unknown". 0 implies a real number (zero). An empty string implies text was entered but it was blank. NULL means the value is absent entirely.
🧠 Checkpoint

Design a table for your notes manager. What columns would it have? What data type for each? Which column is the primary key? Which columns could be NULL?
